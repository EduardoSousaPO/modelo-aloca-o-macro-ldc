## 2. Como usar o cliente (receita de um extrator)

```python
from datetime import date

from apps.pipeline.common import (
    ClienteHTTP, arquivar_bruto, caminho_destino_raw, exigir_contagem_minima,
    fatiar_janela, nome_arquivo_raw, obter_logger, para_data, para_float_ptbr, FormatoData,
)
from packages.shared.schemas import ExtractorConfig, Fonte

_log = obter_logger(__name__)

CONFIG = ExtractorConfig(                     # o contrato é a configuração — não hard-code nada disto
    nome="bcb_sgs_ipca", fonte=Fonte.BCB_SGS, series_ids=("IPCA_MENSAL",),
    base_url="https://api.bcb.gov.br/dados/serie/bcdata.sgs.433",
    formato="json", encoding="utf-8",
    janela_maxima_dias=None,                  # mensal não tem limite; diária usa JANELA_SGS_RECOMENDADA_DIAS
    contagem_minima_esperada=249,             # assert anti-truncamento (CA-001)
    destino_raw="data/raw/sgs",
    valor_canario=("2026-09-01", 0.82),
)

cliente = ClienteHTTP(CONFIG)
tudo: list[dict] = []
for inicio, fim in fatiar_janela(date(2006, 1, 1), date(2026, 9, 30),
                                 janela_maxima_dias=CONFIG.janela_maxima_dias):
    tudo += cliente.json_array(           # GET + validação de shape + guarda de contagem num passo
        "/dados", params={"formato": "json",
                          "dataInicial": inicio.strftime("%d/%m/%Y"),
                          "dataFinal": fim.strftime("%d/%m/%Y")},
        minimo=None,                      # o mínimo do contrato é o TOTAL, não o da fatia
    )
exigir_contagem_minima(len(tudo), minimo=CONFIG.contagem_minima_esperada, origem=CONFIG.nome)
```

Sem fatiamento (o caso comum), `cliente.json_array("/dados")` já aplica
`CONFIG.contagem_minima_esperada` sozinho — não precisa chamar `exigir_contagem_minima` à mão.

Pontos de entrada, por necessidade:

- **JSON array** (SGS, Olinda, SIDRA, B3, MSCI, Yahoo): `cliente.json_array(...)`. Já recusa corpo
  vazio, HTML, `{"error": ...}`, objeto no lugar de array, **e série abaixo de
  `contagem_minima_esperada`**. **Não use `json.loads` direto.** A ordem é shape → contagem: corpo
  de erro dá `RespostaDeErroComStatus200` (diagnóstico certo), não "série curta".
- **Binário / texto** (XLSX do S3, CSV do Tesouro, `ms*.txt`): `resposta = cliente.get(...)` e depois
  `exigir_formato(resposta.conteudo, FormatoDetectado.XLSX, origem=resposta.url)`.
- **POST de formulário** (Curva Zero `CZ-down.asp`): `cliente.post(dados={...})`.
- **Arquivo grande com revalidação** (Tesouro 14,6 MB, R21): `cache_condicional=True` no contrato +
  `etag, last_modified = validadores_condicionais(alvo)` → `cliente.get(etag=..., last_modified=...)`
  → se `resposta.nao_modificada`, reaproveite o arquivado. A **política** por fonte é F-030; a
  primitiva já está pronta.
- **Teste**: injete `transporte=` (qualquer callable com a assinatura de `Transporte`) e devolva a
  fixture gravada. `TransporteGravado` em `tests/unit/test_common_http.py` serve de modelo — copie em
  vez de importar de outro arquivo de teste.

Arquivamento do bruto, sempre assim (idempotente, com manifesto `.meta.json`):

```python
resultado = arquivar_bruto(
    resposta.conteudo,
    destino=caminho_destino_raw(CONFIG),
    nome=nome_arquivo_raw("IMAB", data_ref=date(2026, 10, 9), extensao="xlsx"),
    origem=resposta.url, obtido_em=resposta.obtida_em, cabecalhos=dict(resposta.cabecalhos),
)
if resultado.idempotente:
    _log.info("nada mudou: %s", resultado.caminho.name)
```

## 3. Armadilhas — leia antes de codar

1. **Número: existem DOIS normalizadores, e usar o errado é erro de escala silencioso.**
   `para_float_ptbr` para vírgula decimal (B3 `"38.484,84"`, ANBIMA, Tesouro, Curva Zero);
   `para_float_ponto_decimal` para ponto decimal (JSON do SGS `"0.82"`, Yahoo, MSCI).
   `para_float_ptbr("0.82")` **levanta** em vez de devolver `82.0` — é de propósito. Em pt-BR **todo
   ponto é milhar**: `"6.930"` → `6930.0` (é o vértice do `CZ` em dias).
   **A convenção vale só para texto.** Número **já tipado** (o `float` que `openpyxl` e `pandas`
   entregam) passa direto: `para_float_ptbr(1.234) == 1.234` e
   `para_float_ptbr(723.070317) == 723.070317`. Cobre `int`, `float` e escalares do numpy
   (`float32/64`, `int32/64`); `NaN` → `None`; `bool`, `inf` e tipo não suportado (`Decimal`,
   `bytes`) **levantam** em vez de serem estringificados. Idem `para_data(20261008, AAAAMMDD)`.
   *(Era o bug **QA-01 (P0)**: a entrada numérica ia por `repr(float(v))` e a string com ponto
   decimal era relida como milhar — `1.234` virava `1234.0`, erro de 1000x silencioso, no caminho
   exato de F-002. Corrigido + 8 testes de regressão.)*
2. **Ausência é `None`, nunca `0`** (Anti-SPEC §10.1.4). `""`, `"-"`, `"ND"`, `"N/A"` → `None`.
   Célula vazia de feriado no unpivot da B3 é linha omitida ou `NULL` (CA-037).
3. **Encoding é argumento obrigatório.** `ler_texto(conteudo, encoding)` não tem default; o mapa
   medido está em `ENCODING_POR_FONTE` (latin-1: ANBIMA web, Tesouro, CVM, COTAHIST · UTF-8: IBGE,
   Olinda, SGS, B3, XLSX do S3). Existe um **lint próprio** em
   `tests/unit/test_common_parsing.py::test_ca022_nenhum_leitor_do_pipeline_confia_no_encoding_do_locale`
   que varre `apps/**/*.py` por AST: `open`/`read_text`/`read_csv`/`to_csv` sem `encoding=` **quebra
   o CI**. É intencional (CA-022, Anti-SPEC §10.4.26).
4. **Decida o leitor por magic bytes, nunca por extensão.** `.xls` do S3 da ANBIMA é XLSX (`PK`);
   `.xls` do `CZ-down.asp` é HTML `<table>`. `detectar_formato` → `FormatoDetectado`; `xlrd` não
   entra no projeto (`DECISIONS_LOG §2`).
5. **Data: declare o formato.** `01/02/2006` é 1/fev no SGS (`DD_MM_AAAA`) e 2/jan na PTAX do Olinda
   (`MM_DD_AAAA`). `para_data` não adivinha nem tenta o próximo formato: levanta.
6. **HTTP 200 não é sucesso** (R1, Anti-SPEC §10.1.5). Se você fizer `requests.get` direto, perdeu a
   guarda. O SGS devolve o erro de janela de 10 anos com status 200.
7. **Série diária do SGS rejeita janela > ~10 anos.** Use `fatiar_janela(...,
   janela_maxima_dias=JANELA_SGS_RECOMENDADA_DIAS)` (≈5 anos, margem da pesquisa). Mensal e
   trimestral: `janela_maxima_dias=None`.
8. **Declare `contagem_minima_esperada`** no seu `ExtractorConfig`: `json_array()` **já aplica**
   a guarda no caminho padrão (corpo `[]` com HTTP 200 e mínimo 249 → `RespostaTruncada`). Sem o
   mínimo declarado, Olinda/Yahoo/FRED truncam sem sinal (R2).
   **Em janela fatiada, cuidado:** o mínimo do contrato é o **total** da série, não o da fatia —
   passe `minimo=None` dentro do laço e chame `exigir_contagem_minima` uma vez no total
   concatenado (é o que a receita de §2 faz), ou `minimo=<esperado da fatia>` se souber o número.
   *(Era o furo **QA-02 (P1)**: a guarda existia e nunca era chamada.)*
9. **`arquivar_bruto` não sobrescreve conteúdo diferente** no mesmo nome: levanta
   `ConteudoDivergente`. Isso protege a janela rolante da ANBIMA (R8). Se você *quer* sobrescrever,
   passe `sobrescrever_se_diferente=True` explicitamente e justifique.
10. **`gravar_processado_parquet` valida com pandera antes de escrever.** Use-a em vez de
    `to_parquet` direto: é o que faz "não grava nada em `data/processed/`" (CA-003) ser estrutural e
    não uma promessa. Colunas: as 8 de `ProcessedSeriesSchema`, nada mais (`strict=True`).
11. **Nunca monte caminho na mão.** `caminho_destino_raw(CONFIG)` / `caminho_raw("b3")` /
    `caminho_processed(...)` ancoram na raiz do repo, não no `cwd`.
12. **Sua fixture vai em `tests/fixtures/<fonte>/`**, não em `common/` (essa é da infra). A fixture
    **de erro é obrigatória** por extrator (CA-124). `*.xls` é ignorado pelo git: grave como `.xlsx`.

- Nenhum extrator concreto (é F-002…F-008) e nenhuma série no catálogo.
- Nenhuma leitura de XLSX/CSV/HTML: a infra **classifica** o formato; `read_excel`/`read_html`/

  F-001, mas `conftest.py` é arquivo compartilhado e a onda está aberta — ficou como pendência
