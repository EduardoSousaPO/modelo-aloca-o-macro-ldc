## 8. A regra de "sem cálculo", por extenso (é a que o bloco 2 do teste aplica)

Declarada no docstring do teste e no README, porque regra implícita não vale como portão:

1. nenhuma célula de código define **função** (`def`, `async def`, `lambda`) ou **classe**;
2. nenhuma célula usa **operador aritmético** — `+ - * / // % ** @` — nem na forma composta
   (`+=`, `*=`, …). **Comparação** (`==`, `<`) e **combinação booleana de máscara** do pandas
   (`&`, `|`, `~`) são permitidas: recortar linha não é calcular. Essa é a única nuance da regra, e
   é explícita de propósito;
3. nenhuma célula chama **método de agregação ou transformação numérica** do pandas — a lista tem
   29 nomes (`sum`, `mean`, `std`, `corr`, `groupby`, `apply`, `rolling`, `pct_change`, `diff`,
   `quantile`, `resample`, …).

**Consequência prática na escrita do caderno:** `Path / "x"` é `ast.Div` e por isso está fora — os
caminhos saem de `caminho_canonical("figuras/heatmap_v1_revised.svg")`, que é a função de
`io_layers`. E percentual não é `valor * 100`: é `Styler.format({"media": pct})`, passando a função
pública de `apps/analysis/tabelas/ranking_regime_atual.py`.

## 11. Como quebrar esta feature (para o Validation Mode, `AGENTS.md §15`)

1. **Escrever `df["x"] * 100` numa célula** para "ajustar a escala" → quebra
   `test_nenhuma_celula_usa_operador_aritmetico`. É a tentação real: o percentual já formatado sai
   de `pct`, que é função pública de F-024.
2. **Montar `Path(...) / "figuras"`** → é `ast.Div` e cai na mesma trava. Use
   `caminho_canonical("figuras/<nome>")`.
3. **Definir um `def formatar(...)` no topo** "só para não repetir" → quebra
   `test_nenhuma_celula_define_funcao_ou_classe`. Função nova vive em `apps/`.
4. **Commitar com output** (abriu no Jupyter, rodou, salvou) → quebra `test_outputs_limpos` e
   `test_execution_count_zerado`. O fluxo é `nbconvert --clear-output` antes do commit.
5. **Deixar o `nbconvert` gravar o arquivo versionado no Windows** → ele escreve **CRLF** e quebra
   `test_o_arquivo_usa_lf_e_nao_crlf`; o conteúdo fica idêntico e o `sha256` muda, que é
   exatamente o problema de `D-v`. Conferido: o conteúdo célula a célula do arquivo versionado é
   **idêntico** ao que `--clear-output` produz; só o terminador difere.
6. **Trocar o render de `ranking_regime_atual.md` por uma tabela remontada no caderno** → duas
   verdades. O caderno mostra o Markdown que F-024 gravou, não um Markdown próprio.
7. **Ler `internacional_pesos.parquet`** para "completar" a seção 7 → quebra
   `test_a_tabela_de_variancia_minima_fica_fora` e seria Anti-SPEC §10.5.
8. **Escrever uma frase preditiva** em qualquer célula → a guarda de F-024 reprova em dois testes.
9. **Apagar o `id` de uma célula** → o `nbformat` sorteia outro, o `sha256` muda sem o conteúdo
   mudar; quebra `test_toda_celula_tem_id_explicito_e_unico`.
10. **Rodar o teste de acervo numa máquina sem `data/`** → ele **pula** (padrão `Acervo`), e os
    outros 32 continuam rodando. Confirmado: `LDC_IGNORAR_DATA=1` → 32 passam, 3 pulam.
