## 2. A regra, por coluna

> O valor de `(T, coluna)` é o da **última observação cuja divulgação
> (`date_obs + lag_divulgacao_dias`) é ≤ `quarter_end` de `T`** — o último dia **útil** de `T`, que
> é quando a decisão é tomada (SPEC §2). As derivadas são **recalculadas** sobre os níveis
> deslocados pelas funções puras de F-015; nenhuma é copiada da tabela revisada.

`lag_divulgacao_dias` sai **inteiro do `series_catalog`** (nenhum número de defasagem é escrito no
módulo): PIB **60**, IBC-Br **45**, IPCA **10**, Focus/Selic/CDI/curva/câmbio/externo **0**. Série
consumida sem lag resolvível **para o build** (`LagDesconhecido`) — assumir 0 seria reintroduzir o
look-ahead que a materialização existe para eliminar.

### 2.1 Três decisões de régua que o QA deve olhar

1. **O corte é `quarter_end` (último dia útil), não o fim civil.** Na `revised`, série mensal /
   trimestral mira o último dia **civil** (D-a), que em 24 dos 83 trimestres é 1 a 3 dias depois do
   último dia útil; F-015 declarou essa folga como data de *referência*. Na `asof` ela deixa de
   existir. Efeito prático nulo nas colunas de lag 0 (são diárias) e irrelevante nas de lag > 0 (o
   corte é dominado pela defasagem) — mas é a leitura literal de "só informação conhecida até o
   último DU de T".
2. **Tolerância de frescor = 5 d.u. + 1 período da série** (`tolerancia_de_frescor`). Os 5 d.u.
   secos de F-014 recusariam **toda** célula defasada (a publicação mais recente disponível no fim
   de `T` é, por construção, de até um período atrás) e `ibcbr_*` sairia 100 % nula — nula por
   regra de frescor, com cara de ausência legítima. O termo do período corrige isso; o teto
   continua cortando série morta (`MOTIVO_DIVULGACAO_VELHA`, testado).
3. **`lag_dias` da procedência é o maior lag entre os insumos da coluna.** `surpresa_pib` (PIB 60 ×
   Focus 0) só é conhecida 60 dias depois do trimestre: o máximo é o limite **superior** correto e
   torna `date_obs + lag_dias ≤ quarter_end` uma conta conservadora e verificável no Parquet.

## 4. O teste central (CA-072), e como ele é verificável sem confiar no código

Duas camadas, as duas no acervo real:

1. **na régua** — toda linha de `observacoes_asof` satisfaz `date_obs + lag ≤ quarter_end(T)`
   (testado no sintético, onde a grade é conhecida);
2. **no artefato publicado** — `test_acervo_nenhuma_celula_usa_dado_divulgado_depois_do_fim_do_trimestre`
   junta `macro_quarterly_asof_provenance.parquet` com `macro_quarterly_asof.parquet` por `quarter`
   e exige `date_obs + lag_dias ≤ quarter_end` nas **2.554** linhas. A consulta é escrita **no
   teste**, sem importar a função que o build usa. O relatório publica o mesmo número:
   `anti_look_ahead.celulas_com_divulgacao_depois_do_fim_de_T = 0`.

O build também **para** (`ReproducaoDivergente`) se uma única célula violar a regra — o artefato não
chega a ser publicado.

## 6. Como quebrar esta feature (Validation Mode, `AGENTS.md §15`)

| Tentativa | O que acontece |
|---|---|
| copiar `pib_yoy` da `revised` deslocando uma linha | `test_derivada_do_asof_nao_e_a_coluna_do_revised_deslocada_de_uma_linha` falha (o `ibcbr_yoy` com lag 45 d **não** é deslocamento de linha nenhum) |
| usar o IPCA do próprio fim de `T` | o canário 2 (`date_obs = 2026-08-31`) e `test_acervo_ipca_12m_do_asof_vem_do_penultimo_mes` (83/83) falham |
| assumir `lag = 0` para série sem lag no catálogo | `LagDesconhecido` **para o build**; dois testes negativos |
| deslocar o fluxo diário (`cdi_tri`) | `test_cdi_e_selic_over_nao_deslocam_no_asof` falha |
| arrastar série morta com ffill infinito | `test_serie_morta_nao_e_arrastada_para_sempre` falha |
| publicar a tabela meio `asof`, meio `revised` | `lag_adjusted_homogeneo` recusa (2 testes, wide e procedência) |
| alterar `MacroQuarterlyProvenanceSchema` em vez de acrescentar | `test_schema_de_f015_continua_recusando_as_duas_colunas_novas` falha |
| mudar a régua e não perceber que mudou o `revised` | `conferir_contra_revised_em_disco` **para o build** |
| gravar por cima de `macro_quarterly.parquet` | `test_build_grava_os_tres_artefatos_e_nao_toca_os_de_f015` falha |
| ler o relógio no módulo | `test_o_modulo_de_producao_nao_le_o_relogio` falha |

**Onde o cálculo pode estar errado sem o teste pegar** (para o QA):

1. **`lag_divulgacao_dias` é uma defasagem típica em dias civis**, não o calendário real de release
   por data. Se o IBGE atrasar um release específico, a `asof` daquele trimestre é otimista.
   Arredondar o lag **para cima** é conservador (descarta informação, nunca cria look-ahead) — mas
   os valores do catálogo (60/45/10) não foram auditados release a release.
2. **A perna de `vintage` é degenerada.** `raw_series` tem **1 safra por série** (medido: 0 de 62
   com mais de um `vintage`), então esta `asof` respeita a **divulgação** mas usa a série
   **revisada de hoje**. O efeito de look-ahead publicado é um **piso**, não o total — a revisão
   anual do PIB não está nele. Declarado em `relatorio_asof.json → limitacoes.vintage_unico`.
3. **O proxy de quadrante não é a V1.** Sem o desempate por herança, sem `n` por quadrante, sem
   `especificacao_congelada`. O 29,85 % é um indicativo; o número de CA-073 é de F-019.
4. **`pib_qoq_sa` é nível publicado pelo IBGE** (variação T/T-1 dessazonalizada), e na `asof` a
   linha `T` carrega a variação **de `T-1`**. Quem ler a coluna como "variação do trimestre T" sem
   olhar `lag_adjusted` erra de trimestre — é o risco que a flag existe para cobrir.
5. **A tolerância de frescor é uma escolha** (5 d.u. + 1 período). Mais apertada zeraria colunas;
   mais larga arrastaria série morta. Não há CA sobre ela.
6. **A grade de apoio (`2001Q1..2005Q4`) é a de F-015** e, na `asof`, também é defasada — o `T-4`
   de `2006Q1` vem de `2004Q4`/`2005Q1` conforme o lag. Nenhum teste compara o apoio defasado com
   uma fonte externa (não existe uma).

## 7. Nota para F-019 (e para F-021/F-022)

> **Rode a V1 sobre as duas materializações e reporte o % de trimestres que trocam de rótulo.**

- as duas tabelas têm o **mesmo schema** e a mesma grade: trocar de materialização é trocar o
  caminho do Parquet (`macro_quarterly.parquet` → `macro_quarterly_asof.parquet`). A coluna
  `lag_adjusted` da linha diz qual foi lida — e `RegimesV1Schema` já tem `lag_adjusted` e
  **`trocou_vs_revised`** para carregar o resultado;
- a **`asof` é o default para decisão** (SPEC §2, Anti-SPEC §10.2.7); a `revised` é legítima para
  descrição histórica e **sempre rotulada**;
- o proxy desta feature mede **29,85 % (20 de 67 trimestres comparáveis)**, **acima** do limiar de
  25 % de CA-074. Se a V1 oficial confirmar a ordem de grandeza, o texto do entregável **tem** de
  afirmar que o modelo **não é operacional nessa forma** (hipótese H-03 do PRD cai) — e isso vai
  para a página de limitações, não para uma nota de pé;
- os 20 trimestres que trocam no proxy: `2009Q4`, `2010Q2`, `2011Q1`, `2013Q2`, `2013Q3`, `2013Q4`,
  `2014Q1`, `2014Q4`, `2017Q1`, `2018Q1`, `2019Q1`, `2019Q2`, `2019Q4`, `2020Q1`, `2021Q4`,
  `2022Q1`, `2023Q4`, `2024Q1`, `2024Q2`, `2025Q2`. Note a concentração em **1º trimestres** e em
  **viradas de ciclo** — é onde a defasagem de 45 d do IBC-Br mais muda o sinal do hiato;
- **cuidado com o eixo de crescimento:** na `asof`, `ibcbr_gap` vem do IBC-Br do **1º mês de `T`**
  e a tendência de 20 trimestres é refeita sobre essa série. `ibcbr_gap` muda em **68 dos 83**
  trimestres, com `max |dif| = 8,01 pp`. É o eixo mais sensível da V1 — e a razão de o % de troca
  ser alto;
- **V3 (F-021):** as 6 features de `FEATURES_V3` saem desta tabela. Em `asof`, 4 das 6 são
  idênticas (`z_juro_real_exante`, `z_inclinacao`, `z_usdbrl_var_12m` e o que vier de
  `ipca_desvio_meta`, nulo por G-02) e **`z_ibcbr_gap` muda em 82 %**. A variante `somente_passado`
  do z-score é ortogonal a isto: uma coisa é **quando o dado foi divulgado** (F-018), outra é
  **que amostra estima média e desvio** (F-021).
