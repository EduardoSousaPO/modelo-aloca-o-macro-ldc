## 1. O que a feature faz

Um comando reconstrói a camada canônica, confere o hash e congela o dataset:

```bash
python -m apps.pipeline run --offline              # de data/processed (sem rede) - 11 etapas
python -m apps.pipeline run --online               # os 9 extratores + as 11 etapas
python -m apps.pipeline run --offline --ate build_raw_series     # para no ponto pedido
python -m apps.pipeline run --offline --so regimes_v3            # retoma uma etapa
python -m apps.pipeline run --offline --listar-etapas            # lista a ordem e sai
python -m apps.pipeline verify                     # recalcula sha256 x MANIFEST.json (rc != 0 se divergir)
python -m apps.pipeline freeze --tag comite-2026-10-14           # MANIFEST.json + FROZEN.txt
```

**Arquivos da feature:** `apps/pipeline/run.py` (implementação),
`apps/pipeline/__main__.py` (entrada fina), `tests/unit/test_pipeline_run.py` (38 testes),
`tests/e2e/test_reprodutibilidade.py` (6 testes, N3), este pack e o runbook.
`pyproject.toml` **não** foi tocado: sem `[project.scripts]`, o comando oficial é
`python -m apps.pipeline`.

## 3. Decisões desta feature (candidatas a `DECISIONS_LOG`)

- **(a) `--offline` não toca `data/raw/`.** A fonte do modo offline é `data/processed/` — é o que a
  fixture versionada consegue montar e o que o runbook preserva. Reprocessar `raw -> processed` sem
  rede é explícito (`--reprocessar`).
- **(b) `ldc.duckdb` fica fora do hash agregado, declarado.** **Medido:** em diretório criado do
  zero, duas escritas do `.duckdb` dão o **mesmo tamanho (274.432 B) e `sha256` diferente**
  (`09e048a0…` vs `050d354a…`); reescrita **sobre um arquivo já existente** sai idêntica. Como o
  caso que importa (CA-118/CA-119: máquina limpa, `data/` vazio) é o primeiro, o artefato entra no
  `MANIFEST.json` com `determinista: false`, **`sha256: null`** e o motivo escrito, fica fora do
  agregado e o `verify` o reporta como `INFO`. Ele é derivado e descartável (ADR-006 §(a).2 —
  *views* sobre o Parquet). `run --offline --sem-duckdb` deixa o diretório integralmente
  determinístico.
- **(c) O manifesto cobre `data/canonical/` recursivamente.** `data/canonical/figuras/` (F-025) é
  publicado junto com as tabelas; artefato publicado fora do manifesto é artefato que o `verify`
  não protege. Nome no manifesto = caminho relativo POSIX (`figuras/timeline_regimes_dados.parquet`),
  para a ordem do agregado ser a mesma no Windows e no Linux.
- **(d) Nada lê o relógio.** `data_do_dado` sai dos relatórios das features (`date_max`/`vintages`
  de `raw_series`, primeiro/último trimestre de `macro_quarterly`). É o que faz o `MANIFEST.json`
  sair **byte-idêntico** em duas execuções e o que faz `FROZEN.txt` dizer a data **do dado**.
- **(e) `freeze` não executa git.** O commit vem de `.git/HEAD` + `refs/` (leitura pura); a tag
  continua ato humano (`infra-ops.md §1.3`), e a instrução pronta (`git tag -a <tag> -m "... 
  DATASET_SHA256=<agregado>"`) vai no manifesto e no `FROZEN.txt`.
- **(f) Etapa opcional com módulo presente mas sem `construir()`/`main()` é PULADA com aviso**, não
  falha. Aconteceu de verdade: `apps/analysis/figuras/` existia sem ponto de entrada enquanto F-025
  era escrita. Falha **dentro** do `construir()` continua parando o pipeline.
- **(g) Agregado no formato `sha256sum`:** `sha256` do corpo `"<sha256>  <arquivo>\n"` dos
  artefatos determinísticos, ordenados por nome, terminador LF — reproduzível na linha de comando,
  como `infra-ops.md §1.2` pede.

## 6. O que o QA deve tentar quebrar (Validation Mode, `AGENTS.md §15`)

1. Rodar `run --offline` duas vezes e conferir o `diff` do `MANIFEST.json` — **tem** de ser vazio.
   Se não for, veja antes se algum `.py` de `apps/` mudou no meio (é `versao_build`, não o dado).
2. Alterar 1 byte de um Parquet e rodar `verify` → `rc = 1` nomeando o arquivo **e** o agregado.
3. Apagar um Parquet → `verify` reprova por `ausente em disco`. Criar um arquivo novo →
   `nao listado no manifesto`.
4. Trocar `ldc.duckdb` por lixo → `verify` **aprova** com linha `INFO` (decisão (b)). Se isso
   incomodar, a alternativa é `--sem-duckdb` no congelamento, não mudar o verify.
5. `run --offline --ate alinhamento` sobre um `data/processed/` incompleto → tem de **parar** na
   etapa, nomeá-la, dizer o que não rodou e imprimir `--so alinhamento`.
6. `freeze --saida` apontando para fora de `data/` → recusa.
7. `run --online --so extract_sgs --raiz <tmp>` → recusa (extração sempre grava na raiz do repo).
